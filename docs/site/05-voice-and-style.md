# Wanix Site — Voice & Style Guide

VOICE & STYLE: confident but not hypey; precise and honest (never overclaim — respect the gaps/caveats from research); concrete (show real commands, real file paths like #kv/<key>, real 9P semantics); Plan 9 heritage worn lightly and explained, not assumed; welcoming to newcomers while letting experts skim. Each page starts with YAML frontmatter (title, description, audience, section, related, sourceRefs) then a one-paragraph "what & why", then the body per its outline, then a "See also / next" footer linking related concepts/flows. Use fenced code blocks for commands and file interactions. Prefer short paragraphs and scannable headings.

> The exemplar pages under `docs/site/content/` are the canonical style anchors. New pages should imitate their structure (frontmatter → what & why → body → see also).
