# Wanix Rust Port — Merged Strategic Plan (2026-06)

Merged synthesis of two independent 9-lens research passes (Claude + Codex) plus
direct code verification. Claude's pass contributed the primitive/architecture
framing ("almost everything is `impl FileSystem` + `namespace.bind`"); Codex's pass
contributed the product sequencing ("make Wanix pleasant to write programs for first,
then layer HTTP / agents / collab / data on top") and two factual corrections that
were verified against the code (below). Detailed designs live in the Appendix.
Codex's standalone report was not published into this tree; its surviving findings are folded into the sections below.

---

## 0. Two insights, both kept

1. **Architecture (Claude):** almost every ambitious feature is the same shape —
   `impl FileSystem` + one `namespace.bind(...)`. `#term`/`#task` are the templates;
   the proposed `#pipe`, `#http`, `#kv`, `#doc`/`#crdt`, `#agent`, `#session`,
   `#trace` all copy it. The roadmap is one substrate move reused, not N projects.
2. **Product (Codex):** sequence by *user pleasure*, not by architectural layer. Ship
   the authoring loop (pipes + SDK + templates + `/bin`) first; the weird/differentiated
   demos (capsules, rewind) land better once the boring loop feels solid.

Five **keystone primitives** unlock most of the rest:

| Primitive | Unlocks | Effort |
|---|---|---|
| Service-fs + bind (exists) | every `#device` | — |
| **Pipes** (`#pipe` + shell `\|`) | userland, coreutils, plumber, pipelines | M |
| **Session principal** (identity at 9P attach → namespace provider) | multi-user, auth, presence, federation, worker/agent isolation | M (structural half is S) |
| **Snapshot + namespace-manifest** | capsules, rewind, FaaS cold-start, reproducibility | M |
| **Watch/notify** (blocking read) | live editor refresh, presence, CRDT sync, warm HTTP workers | S–M |

### 1b. Service discovery driver drift — verified, hand-built string
```
roots.rs:110-111   register_driver("qjs")  +  register_driver("wasm")
discovery.rs:149   "...\"drivers\":[\"noop\",\"qjs\"]"   ← hardcoded literal
```
Drifted both ways: `wasm` is registered-but-hidden, and the advertised list is a string
divorced from the registry. Fix = derive from the registry **and** replace the hand-built
JSON with a typed serde struct (the literal at `discovery.rs:149` is the proof-case for
Codex's "typed discovery JSON" recommendation).

## 2. Merged roadmap

### Phase 0 — Same-day hygiene (iteration-trust fixes)
1. **Confirm + regression-test + fix the qjs ES-module exception swallow.** A module-syntax
   top-level throw exits 0 with empty stderr (`runner.rs:64` discards the module-eval
   promise rejection; the CLI error path is ready but never fed). **Top correctness issue** —
   all modern qjs examples use `import`. Nothing else matters if mistakes fail silently.
2. **Fix discovery drift** (§1b): derive `drivers` from the registry, kill the hardcoded
   string.
3. **Cap/account `serve` worker threads** + replace busy-poll accept (`concurrent.rs` —
   unbounded mode spawns detached threads with no cap/backpressure). Needed before HTTP
   workers / remote / multi-user.
4. **Typed discovery/handoff JSON** — serde structs + a shape-pinning test (folds into #2).
5. **Refresh CLAUDE.md follow-ups** — the 6 split targets are already done (largest prod
   module 200 lines, baseline file empty); point pressure at session/serve boundaries,
   discovery drift, and test organization instead.
6. **(Claude add) Structural-only `SessionPrincipal` + namespace-provider refactor through
   `handle_attach`** — behavior-preserving (all identities → current shared root). *Pull the
   structural half forward; leave auth policy in Phase 4.* Rationale: HTTP workers (Phase 2)
   and the agent sandbox (Phase 3) both grow namespace-scoping assumptions; threading the
   principal through attach is trivial now and expensive to retrofit after two subsystems
   assume the global namespace. *(Ship-now vs its-own-cycle gated on a feasibility check.)*

> Architecture health is otherwise excellent: zero `unwrap`/`expect`/`panic`/`unsafe`/`TODO`
> in production across 13 crates, clean dependency DAG, every module under the line limit,
> locking discipline verified clean. Phase 0 is additive hygiene, not remediation.

### Phase 1 — Developer Kit v0 **including pipes**
Codex said "Dev Kit first"; Claude's correction: `/bin` without pipes is far less
compelling. Merged deliverables:
- `#pipe` service filesystem + shell `a | b` + PATH resolution + `/bin` userland
- `/lib/wanix` JS SDK + `.d.ts` for `qjs:std`/`qjs:os`/`scriptArgs`/service files + `tsconfig.wanix-qjs.json`
- `wanix new qjs|qjs-ts|rust-wasm` + a smoke-test harness for templates
- first `/bin` commands, tiny + composable: `help`, `tree`, `grep`, `wc`, `taskctl`, `demo`
- **Guardrail:** do NOT reintroduce `globalThis.Wanix`. Guests keep using ES modules,
  `qjs:std`/`qjs:os`, `scriptArgs`, stdio, env, service files.
- **Hard ordering:** Phase-0 item #1 (error visibility) ships *before* the SDK — the SDK
  is the code everyone writes; debugging it under silent failures is the worst first impression.

### Phase 2 — Workbench as daily driver + HTTP programs
Workbench: run active `.js`/`.wasm`, show `#task` table/exit state, qjs-shell terminals,
TS/qjs diagnostics, HTTP-handler preview; **live refresh once watch/notify exists**.
HTTP: loopback-first, task-backed. First milestone deliberately simple — **manifest route
(`wanix.toml`) → spawn qjs/wasm task → stdout = response body**, with body limit + execution
timeout. Request via fd0/request files, response via stdout/response files. *Later:* the
full `#http/<id>` device (`meta`/`headers`/`body`/`status`/`resp-headers`/`resp-body`/`ctl`,
Appendix C) and the VFS-as-object-store/`#kv` bucket model.

### Phase 3 — Agentic Wanix from the real COZ branch
Host-side service, not qjs magic. `wanix-agent`/`wanix-ai` crate, `AgentEngine` trait with a
**fake backend for deterministic tests**, a `CodexAppServer` backend *adapted from the
worktree in §1a*, exposed as `#agent`/`#ai` (later `#task/new/agent`). Layout
(`#agent/<id>/{prompt,events,text,pending,ctl,status,transcript}`, Appendix B). Two
load-bearing ideas: **approvals as files** (codex approval/elicitation requests park in
`pending`; `ctl` approve/deny; default-deny when no reader), and **Wanix as the agent's
sandbox** (route codex `fs/*` → namespace ops, `command/exec` → `#task`+`#term`+fd bindings)
so the agent works in the same world as the shell, workbench, HTTP programs, and VM/9P clients.

### Phase 4 — Session/auth floor (before collaboration or CRDT sync)
Builds on the Phase-0 structural refactor. Add token policy for non-loopback, discovery
auth metadata, terminal ownership + read-only/shared attach, `#session/who`, presence/room
log, workbench session display. *Only then:* shared terminals, file-watch events, Automerge
sync, remote workbench/v86 routes. Protects the host-root serving model from silently
becoming a remote write API.

### Phase 5 — Durable state: `#kv` → `#doc` → CAS → sync
`#kv` first (smaller foundation than jumping to Automerge): map backend → durable append-log/
directory backend. Then `#doc` (Automerge documents on storage), a content-hash blob/object
store (docs reference blobs, never embed large binary state), and eventually `#crdt` changes
stream + loopback-only sync route. All host-side services through files, no qjs globals.
**Build the watch/notify primitive here or in Phase 2 — whichever consumer lands first — once.**

### Phase 6 — Differentiated demos: record/replay → capsules
Small milestone first: run one qjs program with deterministic-ish clock/random; capture
stdout/stderr + terminal bytes + VFS mutation summary + task metadata + final filesystem
digest as JSONL; replay and assert identical digest/output. Then the big swing: QuickJS
snapshot bytes + task env/cwd/argv/kind + namespace manifest + backing refs (CAS / 9P / inline)
→ freeze/thaw into a `.wcap`, resumable across native / browser / VM (Appendix H). Do NOT
pull this before qjs errors, pipes, SDK, PATH, and workbench feel solid.

## 3. Priority summary

```
0  qjs module errors • discovery drift • serve thread accounting • (structural session seam)
1  #pipe + Developer Kit v0 (SDK, .d.ts, templates, /bin)
2  workbench daily-driver + loopback HTTP programs
3  #agent/#ai from the real COZ app-server worktree
4  session/auth floor
5  #kv → #doc/Automerge → CAS → sync
6  record/replay → capsules
```

**One thing next:** Phase-0 #1 (silent-module fix) — tiny, makes the platform trustworthy
to iterate on. **Widest blast radius:** the SDK (Phase 1) and the structural session seam
(Phase 0 #6). **Defining demo:** compute capsules (Phase 6), but not before the authoring
loop is pleasant.

## 4. Cross-cutting guardrails (both reports agree)
- Keep lower-level crates free of runtime engines; new power behind host-side service files.
- No `globalThis.Wanix`; guests interact via WASI / VFS / stdio / env / service files.
- Don't hold a namespace/filesystem lock while calling into another filesystem or engine.
- Public/network routes loopback-only until auth + session identity are explicit.
- Prefer qjs/wasm differential tests for user-facing behavior.
- QEMU/v86 stay handoff clients, not Wanix-supervised VM lifecycle, until contracts harden.

## Boil-the-ocean — the aggressive bets, with architecture

The agent is now a confined operator of a Wanix world. The big swings from here,
each concrete:

1. **✅ The agent runs Wanix programs.** `ExecServer`'s process step is pluggable
   (a `ProcessRunner`); `wanix-cli` wires `qjs FILE`/`wasm FILE` to the real task
   runtime against the agent's namespace. Tested: a qjs program written into a
   MemFs world runs and its stdout is captured. The LLM writes a program and runs
   it.
2. **✅ Agent as a network service.** `serve` reads POST bodies; `POST /agent`
   (loopback-only) drives the served `#agent` device and streams the event log.
   Curl-proven: `curl -X POST --data "…" /agent` returns the turn. The agentic +
   webby convergence. (A codex-backed served `#agent`, gated on auth, edits
   `wanix:/` live in the workbench — the natural next turn.)
3. **✅ Recursive multi-agent.** The services namespace contains `/#agent`, and a
   new `#agent/<id>/reply` file (a single blocking read that EOFs at turn end, vs
   the never-ending `events` stream) makes delegation clean: an agent reads
   `/#agent/new`, writes a sub-task, reads `/#agent/<id>/reply`. The developer
   instructions tell it so. Agents consult sub-agents as files.
4. **✅ Capsule worlds.** `wanix capsule save DIR FILE.wcap` freezes a Wanix world
   into a gzipped tar with a content-addressed id (sha256 over sorted per-file
   hashes); `capsule load` restores it to the same id. Proven: the agent's `#kv`
   world froze to a 156-byte `.wcap` (id `0c37b1…`) and restored to the same id.
   Verifiable, shippable worlds.
5. **✅ Agent → VM.** `chmod` in the exec-server lets the agent author an
   executable `/bin/init`; `wanix qemu --root <world>` then emits a complete
   `wanix-qemu-virtio9p.v1` boot handoff. Proven end to end: an exec-server-
   authored guest root produced the exact QEMU command line to boot it as a Linux
   VM over virtio-9p. The agent builds an OS root, confined and observable; the VM
   boots it.

**All five bet built.** The agent now: cats an LLM → edits a confined world →
operates Wanix services (`#kv`) → runs Wanix programs (`qjs`/`wasm`) → delegates
to sub-agents → answers over HTTP → and authors a bootable VM root you can freeze
into a portable capsule. Gated by approval files; confined by the exec-server.

Designed + adversarially verified, ready to implement next (plans in the workflow outputs):

- **HTTP workers** (Phase 2 marquee): `--http-handler PREFIX=SCRIPT`; request body → task fd0, stdout → response. Reuses `attach_task_stdio`/`configure_qjs_task`. Corrections captured: derive Debug/Clone/Eq on the route; path+query from the raw target; loop Content-Length, break on read()==0; 27 `ServeCommand` literals need the new field; body-reading is net-new.
- **Shell `|` + PATH + `/bin`** (Phase 1 userland): blocked on a **key architectural finding** — *a task's exit does NOT drop its fds* (verified: `set_exit` doesn't touch fds, tasks are never reaped, the qjs runner never closes guest fds). So a pipe writer bound to a task's fd/1 stays open after the task exits and the reader hangs forever. Shell `|` therefore needs a new **`close fd/N` ctl verb** (wired to `task.close_fd`) that the shell issues after the left task exits. Also: `/bin` filter programs must be self-contained (the qjs loader resolves imports against the namespace root, which won't contain `lib/wanix/` for a `/bin` script).

# Appendix — detailed designs

## A. Service-filesystem + bind pattern (universal template)
Implement `FileSystem` (parse path → typed enum, synthesize dir listings, return stateful
`File` impls whose `read`/`write` are a protocol), then `namespace.bind(Arc::new(Dev::new()),
".", "#name", BindOptions::default())` in `crates/wanix-cli/src/serve/roots.rs` beside the
`#term`/`#task` binds. Allocation idiom: `read #name/new` → `"<id>\n"`. Control idiom: write
verbs to `#name/<id>/ctl`. Templates: `crates/wanix-term/src/lib.rs` + `files.rs`;
`crates/wanix-task/src/task_files/new_task.rs`.

## B. `#agent`/`#ai` from the COZ worktree
Source skeleton (`/Users/jesse/.codex/worktrees/3583/coz`, branch `codex/app-server-coz-exec`):
`src/chat/app_server.rs` defines `ChatBackend` + `CodexAppServerBackend` + `AppServerClient`
that spawns `codex app-server --listen stdio://`, builds a `.data/codex-home` overlay, copies/
links auth+config from the real Codex home, writes `environments.toml` with a default env, and
drives `thread/start` / `turn/start` JSON-RPC while handling agent-message / command-execution /
dynamic-tool notifications; `src/codex_exec_server.rs` implements process + fs JSON-RPC for that
environment. **Wanix adaptation:** replace the COZ bash/js environment with a Wanix environment —
process start/read/write/terminate via `#task` + `#term`; fs read/write/list/metadata/copy/remove
via the namespace VFS; surface tool calls as visible event streams; keep the app-server process
host-side. Incremental path: (1) fake `AgentEngine` for deterministic tests → (2) local one-shot
agent task → (3) `#agent` service fs → (4) Codex app-server backend → (5) workbench commands.

`#agent/<id>/` layout: `prompt` (write a turn), `events` (normalized JSONL stream), `text`
(agentMessage deltas only, for `cat`), `pending` (open approval/elicitation requests), `ctl`
(start|interrupt|steer|approve <reqid>|deny <reqid>|resume|fork|close), `status`, `transcript`.
**Approvals = files**, default-deny on timeout with no reader; a serve flag sets the default
(`read-only|none|all`). **Sandbox:** the session carries a cloned `Namespace` + `TaskTable`;
codex `fs/readFile|writeFile|readDirectory` → namespace ops, `command/exec` → `#task/new/<kind>`
+ start with fds bound. Risks (from Codex): prompt injection via mounted files; unclear authority
if agents mutate host roots; app-server lifecycle tangling with qjs runtime lifecycle; test
nondeterminism without the fake backend.

## C. `#http` request-as-task protocol
`HttpDevice: FileSystem` at `#http`. Per-request `#http/<id>/`: `meta` (method/path/query, RO),
`headers` (RO), `body` (request stream), `status` (WO, default 200), `resp-headers` (WO),
`resp-body` (task→host stream), `ctl`. Bind `body`→fd0, `resp-body`→fd1 so a handler is "read
stdin, write stdout" (also makes `.wasm` command-style handlers free). After task exit, serve
reads status+resp-headers+resp-body and writes an HTTP/1.1 response (generalize
`StaticResponse::encode`, `serve/http/response.rs`). **Prereq:** `serve/http/request.rs` is
GET-only with no body parsing — add method + Content-Length/chunked reading + a route table
(`--http-handler /api=workers/api.js`, kind from extension). **Object store:** `--bucket
name=<dir-or-fs>` binds a backing FS at `/buckets/<name>` (key→file, prefix→subdir,
list→read_dir; MemFs=ephemeral, LocalFs=durable, 9P-backed=remote); optional `#kv` adds
get/put/list/delete ctl over any backing. **Warm-worker mode** (L): resident qjs task pulling
requests off `#http/next` via the driver's event-loop budget for warm starts + per-worker state.
First milestone stays simple: manifest route → spawn → stdout response.

## D. TypeScript — ambient defs + strip pipeline
Code OSS already bundles the TS language service, so editor checking ≈ "drop `.d.ts` + tsconfig
into the served namespace." Ship `qjs:std`/`qjs:os` ambient modules + globals (`scriptArgs`,
`print`) keyed to the fixture's real exports (ground truth = the `wanix-qjs` tests); default
tsconfig `target ES2020`, `moduleResolution bundler`, `types:["wanix"]`, `strict`, `noEmit`.
Host-side strip: `oxc_transformer` (lean) or `swc_ecma_transforms_typescript`, at the entry read
(`runner.rs::run_task_with_runtime_limits`) and the module loader
(`host_api.rs::define_wanix_module_loader`, with `.ts`→`.js` resolution); teach
`QuickJsTaskDriver::check` to claim `.ts`. Type *stripping* only (isolated-modules); full
in-Wanix type *checking* is blocked today (esbuild.wasm is Go-WASM-for-JS-host not WASI; tsgo
has no WASI-command artifact; Rust checkers stc/ezno aren't production-grade). Record the
host-side-transpiler exception in ADR 0002, or use a sucrase `.js` task for purity. Guardrail
(Codex): don't imply Node module semantics inside QuickJS.

## E. Session principal + attach (structural Phase-0 half)
`handle_attach` (`crates/wanix-9p/src/session.rs`) currently decodes `uname`/`aname`/`afid`
then ignores identity and attaches `.`; `handle_auth` returns ENOSYS; `P9Server`
(`wanix-9p/src/lib.rs`) holds one shared `root: Arc<dyn FileSystem>`. Introduce a
`SessionPrincipal` (from `uname`, default anonymous) + a `NamespaceProvider` trait
(`attach(principal, aname) -> Arc<dyn FileSystem>`); the trivial default provider returns the
current shared root for every principal (ZERO behavior change). `P9Server::new` takes a provider
with a `from_root` convenience wrapping a fixed root, so the existing call sites
(`p9_ws/connection.rs`, `p9_listen/runtime.rs`, `p9_stdio.rs`, `qjs_restore.rs`, plus
serve/roots wiring) barely change. `aname` later selects the attach tree (empty→shared,
`home`→private overlay, `room:<id>`→collab room). Auth/token policy stays Phase 4. Guardrail:
assemble per-session namespaces without holding the registry lock across binds.

## F. Pipes + plumber + ports
`Channel { buf: Mutex<VecDeque<u8>>, writers_open: AtomicUsize, condvar: Condvar }`. `read`:
drain, or `Ok(0)` EOF when `writers_open==0`, else block on condvar with a bounded timeout (so
the qjs event-loop budget stays responsive — on timeout return `WouldBlock` for
`poll_oneoff`/`setReadHandler` to re-poll). `write`: append + notify; final writer close
decrements + notifies. `#pipe/new`→id; `#pipe/<id>/data` read→reader, write→writer. Shell
`a | b`: alloc pipe, `bind #pipe/<id>/data fd/1` on left, `fd/0` on right, inherit outer
fd0/fd1/fd2 (exactly today's redirection binds), start both. EOF correctness needs task teardown
to drop `OpenFile` clones so `writers_open` reaches 0. `#plumb` = a named multi-reader channel
on the same core. `#ports`: `catalog` (embedded JSON), `installed`, `get` (write a name → copy
bundled blob into `/bin`, set exec). PATH: literal if it contains `/`, else search `PATH`
(default `/bin`) for `<argv0>{,.js,.wasm}`, kind from extension via `#task/new/auto`.

## G. Data — `#kv` → `#doc`/`#crdt` + watch
`#kv/<key>`: read=value, write=set, remove=delete, read_dir=list; map backend first, then
append-log + content-addressed store reusing `wanix-module-cache` atomic-write/fd-trust. `#doc`
(Automerge): `#doc/new`→id, `#doc/<id>/json` (materialized), `/heads`, `/ctl`; later `/changes`
(binary change stream, blocking read = the watch primitive; write = merge). Two instances
exchange `changes` and converge, zero guest conflict logic. Keep large blobs in the CAS/object
store, referenced by hash from docs — never embedded in Automerge state. Converge test mirrors
`shared_vfs_differential`. CRDT-backed *filesystem* (L swing): Automerge root `entries:
Map<name, Node>`, text files use `Text` (char merge), binary = whole-file LWW (ADR the tradeoff).

## H. Capsule + rewind (shared mechanism)
Checkpoint = (1) engine snapshot bytes (`QuickJsRuntime::snapshot_bytes()`, captures wasm linear
memory + JS heap; exists), (2) the `snapshot_blockers()` precondition (no live external fd —
already enforced), (3) a **namespace manifest** (the one new primitive: serialize `Namespace`'s
bind table to `{destination, source, backing-ref}` where backing-ref is a content hash | 9P
address | inline bytes), (4) task scalars (env/cwd/argv/kind), (5, rewind only) an append-only
log of each WASI call's non-deterministic result. `.wcap` = 1–4; a rewind timeline = 1–4 + the
5-logs between. Thaw/migrate rebuilds the namespace via a per-environment `host_resolver` (CAS
local | 9P-TCP | 9P-WS | virtio-9p) — the capsule is identical everywhere because the engine
bytes are identical Wasmtime memory and the filesystem is late-bound. Rewind restores the
